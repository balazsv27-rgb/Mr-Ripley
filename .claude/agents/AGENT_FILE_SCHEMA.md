# Agent File Schema

> **Generated by:** Step 3 of Implementation Sequence (agent_generation_plan.md Section 18)
> **Purpose:** Defines the exact structure each `.claude/agents/<name>.md` file must follow.
> **Authority:** Derived from agents.yaml definitions and agent_generation_plan.md Section 18 Step 3.

---

## File Naming Convention

```
.claude/agents/<agent_name>.md
```

Where `<agent_name>` is the exact `name` field from agents.yaml (e.g., `claim-classification-agent.md`).

---

## Required Frontmatter

Every agent file MUST begin with YAML frontmatter containing exactly these fields:

```yaml
---
name: <agent_name>                    # must match agents.yaml name exactly
description: <one-line purpose>       # derived from agents.yaml purpose field
model: <opus | sonnet>                # must match agents.yaml model exactly
tools: <tool_list>                    # must match agents.yaml tools exactly
---
```

---

## Required Body Sections

Every agent file MUST contain these sections in this order:

```markdown
# <Agent Display Name>

## Role
<functional role — derived from agents.yaml role field>

## Bound Workflow Step
<step ID from agents.yaml workflow_steps — single step per agent>

## Skill Binding
<skill name(s) from agents.yaml skill_bindings — reference only, do not duplicate skill content>
<If no skill binding (dispatcher agents): "None — this agent dispatches subagents, not skills.">

## Authority Sources
<canonical documents this agent must consult>
<Derived from workflow step inputs that reference Documentation/* paths>
<If none: "Via prior governance artifacts — no direct canonical document consultation.">

## Inputs
<artifacts and documents consumed — must match agents.yaml consumes list>
<Each input on its own line with brief description of what it provides>

## Required Outputs
<artifacts produced — must match agents.yaml produces and artifacts.yaml expected_outputs>
<Each output on its own line with brief description>

## Constraints
<governance constraints from CLAUDE.md, specific to this agent's scope>
<Include only constraints that are directly relevant to this agent's function>

## Failure Mode
<from agents.yaml failure_mode — the exact fail-closed behavior>

## Escalation
<escalation targets and conditions from agents.yaml escalation_targets>
<Format: "subagent_name — triggered when condition_description">
<If none: "None">

## Hook Reinforcement
<hook name from agents.yaml hook_reinforcement>
<Brief description of what the hook enforces>
<If none: "None">
```

---

## Optional Section

If the agent has an `activation_predicate` in agents.yaml:

```markdown
## Activation Predicate
<predicate name from agents.yaml activation_predicate>
<Brief description from predicates.yaml>
<When this predicate evaluates false, the step is skipped.>
```

---

## What Does NOT Belong in Agent Files

- **Skill reasoning instructions** — live in `.claude/skills/<name>.md`, not here
- **YAML schema fields already in agents.yaml** — the file implements the contract, not re-declares it
- **General CLAUDE.md content** not specific to this agent's scope
- **Implementation code or scripts**
- **Duplicate content** from other agent files or source YAML

## Validation Rules

1. Every agent file name must match an agent `name` in agents.yaml
2. No agent file may exist without a corresponding agents.yaml entry
3. Frontmatter `name` must exactly match file name (minus `.md`)
4. Frontmatter `model` must exactly match agents.yaml `model`
5. Frontmatter `tools` must exactly match agents.yaml `tools`
6. `Bound Workflow Step` must match agents.yaml `workflow_steps`
7. `Skill Binding` must match agents.yaml `skill_bindings`
8. `Required Outputs` must match agents.yaml `produces` and artifacts.yaml
9. `Inputs` must match agents.yaml `consumes`
10. `Hook Reinforcement` must match agents.yaml `hook_reinforcement`
11. `Escalation` targets must match agents.yaml `escalation_targets`
12. No subagent may receive an agent file (subagents defined only in subagents.yaml)
