 The revised system-orchestration.yaml has been written. Here is a summary of every fix applied:

  1. Constitution role label corrected
  authoritative_execution_specification → authoritative_normative_constraints, with an explicit note clarifying that CLAUDE.md defines obligations only and does not execute     steps.
                                                                                                                                                                               
  2. Duplicate hook keys removed                                                                                                                                               
  pre-pr-governance-gate had two action / on_fail blocks. Collapsed to one authoritative block using a structured required_artifacts list and additional_checks array.         

  3. Formal predicate system introduced
  New top-level scope_predicates section defines six reusable, machine-readable predicates (runtime_code_scope, adapter_registry_scope, rename_only_change,
  contract_affecting_change, matrix_posture_affected, doc_update_required). Every condition, requires_if, and skip_if in the file now references these typed predicates rather 
  than prose.

  4. rename-invariance-check skill formally declared
  Added to the skills section with role, purpose, workflow_step, produces, and activation_predicate fields. The workflow step's condition / skip_if now use the structured     
  rename_only_change predicate.

  5. DAG-compilable step schema
  Every workflow step has a consistent set of machine-oriented fields: id, layer, component, purpose, inputs, outputs, depends_on, validates, raises, on_block. Conditional    
  steps add condition and skip_if. Escalating steps add escalates_to with typed dispatch predicates.

  6. Blocking conditions normalized
  All 12 conditions now carry: id, raises_at, raised_by, enforced_by_hook, severity, halts_workflow, resolvable, resolution_required.

  7. Hook checks replaced with structured predicates
  Every hook's checks array now uses typed entries (artifact_field_equals, artifact_field_not_contains) against named artifact fields. Hooks declare reads_artifacts to        
  document their runner-state dependency.

  8. Subagent trigger conditions formalized
  All trigger_condition fields now use typed predicates instead of prose strings.

  9. Execution metadata section added
  New execution_metadata block declares workflow_schema_version, predicate_language_version, artifact_contract_version, execution_model, and enforcement_model.

  10. Artifact output ownership enforced
  artifacts.expected_outputs lists every artifact with a single produced_by step id and a required_at_pr_gate_when_predicate where conditional. No artifact is declared as     
  produced by more than one step.

  11. Stage gates normalized to machine-evaluable nodes
  Each gate has allowed_scope, forbidden_scope, a typed check predicate against phase_alignment_status fields, and an on_violation.raises binding.

  12. deep-audit circular reference fixed
  deep-audit dispatch now only references artifacts available at that point in the DAG (A–C layer outputs). Layer-D artifact (doc_code_sync_status) references moved to        
  escalates_to blocks on doc-code-sync-check and update-verification-matrix where those artifacts are actually produced.

  13. change-impact-audit skill YAML structure fixed
  The malformed extended_rules: indentation block (which caused YAML structural ambiguity) replaced with a clean, flat mapping under the skill declaration.
